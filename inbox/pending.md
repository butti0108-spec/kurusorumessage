#### 必須フロー（毎回）
1. 対象リポで **先に `git pull`**（本連絡リポも、書く前に pull）
2. 指示範囲だけ実装（独断で広げない）
3. 自分で動作確認（壊したら戻す）
4. **同じ区切りで** add → commit → `git push origin main`
5. 本リポ `pending` に報告（下記フォーマット）して push
6. 次指示まで止める

**push されてない変更は、クルからは「無い」と同じ。未完了。**

#### commit 粒度
- 1区切り＝1目的（入口だけ／ZIP読み込みだけ、など）
- 無関係ファイルを混ぜない
- メッセージは「何のためか」が分かれば英日どちらでも可

#### 禁止
- Pages 入口削除（`index.html` 等を消したまま push）
- 秘密・トークン・巨大 zip を追跡に入れる
- `docs/確定/` の独断改変（案は進行中）
- force push／git identity の無断変更
- クル確認中に同じファイルを黙って連続上書き（被りそうなら「待ち」と pending）
